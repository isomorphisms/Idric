# Pass 3 — free/bound indices and the Hindley–Milner analogy

There is a useful HM-shaped pattern here, but it should be stated precisely enough not to turn every kind of inference into “Hindley–Milner.”

## The useful analogy

Ordinary HM inference:

```text
unknown type variables
-> constraints generated by syntax/use
-> unification
-> most-general remaining type
-> generalization where permitted
```

Indexed elaboration can use a parallel architecture:

```text
unknown index-space/dimension variables
-> constraints generated by index occurrences and operations
-> unification / dependent normalization / structure solving
-> free boundary indices remain in result type
-> unresolved permissible parameters may be generalized
```

The analogy is strongest at the level of *constraint generation and solving*.

## Free and bound are literal here

A free Einstein index is part of the output interface. A contracted index is locally bound by the product in which its upper/lower occurrences pair.

Thus:

```text
Tⁱⱼ vʲ
```

has `j` bound by contraction and `i` free.

This suggests representing the result type in a way that exposes its remaining indexed interface rather than only a storage shape.

## Alpha-equivalence

If the index is bound, its spelling is irrelevant:

```text
ωᵢ vⁱ
ωⱼ vʲ
```

are the same binding pattern after type/index-space constraints are accounted for.

This is another argument for deleting the literal index name from the semantic graph after binding, while retaining it only in source provenance.

## Where the HM analogy stops

A contraction loop in a tensor graph is **not** an occurs-check failure. Graphs with cycles/traces are perfectly meaningful. The HM occurs check prevents an infinite recursive type equation such as `α = α -> β`; it should not be copied mechanically into graph construction.

Likewise, structure search for a metric, a Frobenius algebra, or a theorem is not ordinary HM unification. The explanation trace should keep these solvers separate:

```text
unification
index-space normalization
structure/interface resolution
law rewrite
theorem lookup
```

## Most-general indexed result

A useful design target is analogous to a principal type: after elaboration, report the least-specific boundary/index information forced by the expression and context.

For example, elementwise addition of two length-`n` objects over the same scalar domain should not invent a concrete `n` if it remains polymorphic. Conversely, a contraction that connects two ports should generate the equality/duality obligation required to make those ports compatible.

The result should be explainable as constraints, not guessed from a pattern name.
